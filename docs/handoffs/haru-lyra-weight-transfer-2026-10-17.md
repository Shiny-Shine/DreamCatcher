# HARU Lyra 근육 가중치 전이 — 2026-10-17

사용자는 HARU 사본에 Lyra 원본 가중치를 전이·검증한 뒤 실사용 HARU에 적용하고, 얼굴·머리카락·손가락·장비의 기존 연결을 보존하도록 승인했다. 0.126의 본89개 추가와 원본 보정 그래프 연결을 기반으로 진행했다. C++ 빌드·패키징·커밋·푸시는 실행하지 않았다.

## 적용 범위

- 실사용: `/Game/DreamCatcher/Main_Charcher/Haru/SKM_HARU`
- 검증 사본: `/Game/Developers/Codex/HaruWeightTransfer/SKM_Haru_LyraWeights_Candidate`

Unreal `AssetTools.duplicate_asset`와 `SkinWeightModifier`로만 복사·가중치 수정·저장했다. 바이너리 파일을 외부에서 복사/변조하지 않았다. 실사용 Mesh의 가중치만 바꾸고 Skeleton, Rig/Post Process, Pawn, 무기/SMG, 애니메이션, Level_1, Config, 소스 FBX는 유지했다. 사본2개는 게임플레이 연결 대상이 아니다.

기존21,999정점 중2,917정점의 가중치가 달라졌다. 얼굴·머리카락·손/손가락·배낭/장식·신발 및 접촉 경계를 포함한 보호18,656정점은 엔진의16비트 가중치 단위로 정확히 일치한다. 선택 영역 중 변경이 없는 정점까지 포함하면19,082정점이 그대로다. 원래60개 가중치 본의 연결을 우선 보존하면서 새 근육 보정 본35개에 가중치를 추가했다. 실제208개＋가상3개 본과 원래 본의 부모·기준 자세는 유지한다.

## 원본과의 차이 및 근거

원본 Manny와 HARU는 형상·정점·의상 구성이 다르므로 정점 번호별 복사가 아니다. 기존 조사에서 실제 Lyra 원본과 일치를 확인한 Manny를 임시 DynamicMesh로 읽고, HARU 기준 자세에 맞춘 뒤 Unreal의 가까운 표면 전이를 사용했다. 임시 형상은 에셋으로 저장하지 않았다.

첫 후보E는 윗팔 정점이 아랫팔에 대응하거나 코트 자락이 과도하게 당겨져 최대 약17cm 변형을 보였다. 저장/보호 검사는 통과했지만 실제 자세 검증에서 거부했으며 실사용에는 적용하지 않았다. 관절 예산 보존만 한I/J/L도 최종본이 아니다.

최종M→N은 다음 제약을 둔다.

1. 코트·몸통/반바지·다리의 지정 부분만 대상으로 삼는다. 얼굴/목/손에 기존 가중치가 있는 정점과 나머지 구성품은 보호한다. 보호 표면과0.75cm 이내는 고정하고2.5cm까지 부드럽게 전이를 늘린다.
2. 기존 HARU 관절별 총 가중치를 유지한다. 팔→다리, 윗팔→아랫팔처럼 다른 관절로 질량을 옮기지 않는다. 원본에서 작은 관절 기여를 대상의 큰 기여로 증폭하지 않는다.
3. 기존 비틀림 가중치와 영향 슬롯을 우선 유지한다. 0.126의 Lyra→CC 회전 연결을 계속 사용하며 새 Lyra 비틀림 본16개로 피부 가중치를 교체하지 않는다. 최대8개 영향 안에서 남은 슬롯에 원본 근육 보정을 넣고 잔여 질량은 기존 연결에 남긴다.
4. 같은 부위의 원본 표면과 거리가 클수록 원래 가중치를 더 남긴다. 거리 신뢰도는 `1/(1+(거리/2.5cm)^2)`이며 HARU 의상 대응을 위한 조정값이지 Lyra 원본 수치가 아니다.

누락 추가 본89개 중 원본 Manny에서 실제 가중치가 있는 본은56개다. 그중35개 근육 보정 본이 이번 전이 대상이 됐다. 비틀림16개는 기존 CC 연결을 유지하고, 손목4개(`wrist_inner/outer_l/r`)는 손 보존 범위다. `upperarm_in_r`은 최종 보호/기존 슬롯 우선 조건에서 가중치를 강제로 만들지 않았다. 나머지33개는 원본에도 피부 가중치가 없는 보조/부모 본이다. 모든 추가 본에 가중치를 억지로 배정하지 않는다.
